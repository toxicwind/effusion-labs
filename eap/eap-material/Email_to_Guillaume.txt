What worked incredibly well:

Being able to return complete function declarations inside `function_result.result` without pre-registering them is a game-changer for large catalogs. Edge cases and friction points:
1. Parameter Hallucination on Deferred Tools: When passing a deferred tool with optional parameters, the `tool_search_result` frequently omitted the optional parameter schema, causing the model to hallucinate during the subsequent `function_call`.
2. MCP Server Latency: Under high concurrency, the synchronous round-trip for `mcp_server_tool_call` steps added noticeable latency to the resolution loop. I ended up implementing a local caching layer in my gateway to bypass this.
